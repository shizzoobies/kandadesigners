A long course rarely needs to be one long course. Split it so each module teaches one thing.

Four steps, one per page in this document:

1. Start from the job, not the chapter list. Write down what people must be able to do after the training. Topics describe the course; actions describe the job, and each action can become a module.
2. Give each module one objective, written as one sentence. If the sentence needs an "and", it's two modules.
3. Make every screen serve that objective. Anything that doesn't goes to a job aid or another module.
4. Let learners do the thing before the module ends. The module should end with the objective done, not just explained.

Then put the modules in the order the work happens.

The example is our RFI sample course. Its one objective is on the first screen: "Turn a drawing conflict into a request the design team can act on." All three steps inside it point at that request, and it ends with the learner building one from field notes, leaving the distractions on the desk. Those screens are real; the chapter list and the three-module split are drawn examples.

The last page is a three-question check to run on every module you build.
